# 形式仕様と出所

- MS-VBAL [TypeOf…Is Expressions](https://learn.microsoft.com/en-us/openspecs/microsoft_general_purpose_programming_languages/ms-vbal/22d0220a-65bc-412a-9052-adb02aadb875) — `TypeOf expression Is type-expression` is Boolean; the value expression must have a permitted declared type, an implemented interface may satisfy the target type, and Nothing raises runtime error 91. The parser retains object/type operands separately and rejects known scalar operands. The analyzer reports exact declared-class and in-project `Implements` relations as compatibility candidates, not runtime truths; it does not evaluate external interfaces or runtime instance values.
- MS-VBAL [Is Operator](https://learn.microsoft.com/en-us/openspecs/microsoft_general_purpose_programming_languages/ms-vbal/4730e541-8747-4259-ae76-128c7024b3b8) — ordinary `Is` requires both expressions to be values declared as a specific class, Object, or Variant and returns Boolean; non-object runtime values raise Error 424. The analyzer reports known scalar/UDT operand violations (`VBA2147`) and leaves dynamic Object/Variant values unresolved.

この実装は公開仕様を確認して独自に記述しています。第三者の逆コンパイラー、既存パーサー、生成済み命令表、VBA文法ファイルからコードを移植していません。仕様の記述そのものをソースコードへ転載するのではなく、構造・境界・アルゴリズムを実装しています。

- Path-specific argument snapshots use the same MS-VBAL argument binding rules plus the analyzer's existing acyclic assignment-state boundary. Only values proven at the call node are reported; mutable aliases, runtime coercions, loops, and incomplete control-flow paths are deliberately omitted.
- Return-path composition uses direct caller/callee relations already established by the bounded path pass. It joins at most two adjacent relations (caller → wrapper → leaf), carries each side's conditions and leaf return expression, evaluates the outer caller's post-return conditions when that expression is supported, and labels the result as a candidate; independently enumerated activations, longer chains, recursion, aliases, and dynamic dispatch are not proven equivalent.
- Scalar ByRef value composition joins a caller path snapshot to an existing callee write candidate and evaluates only the callee's parsed write expression under that formal's seeded value. It records a write-value candidate, not a proven post-call caller state; arrays, aliases, effects, loops, ambiguous calls, and runtime coercions remain unresolved.
- Nested ByRef forwarding can join these candidates through a bounded composition depth when the intermediate write is a known call-forwarding edge; missing expressions are retained as forward candidates and no runtime copy-back proof is claimed.
- Object alias folding uses only a path-local `Set target = source` where both declarations are statically object-compatible; it reuses the source expression for supported type predicates and does not infer runtime identity, default members, Variant payloads, or alias survival across effects.
- Declared array expressions assigned to a Variant are retained as a path-local alias only for `IsArray` shape predicates; dynamic Variant contents and element/member identity remain unresolved.
- ParamArray slot snapshots are emitted only for bounded positional actuals, one fact per zero-based slot; named arguments, omitted positions, and runtime-built argument lists remain unresolved.
- Alias dispatch candidates reuse only a later path-associated member call and a unique visible in-project source member; they are separate evidence and do not rewrite the original call binding or prove runtime identity.
